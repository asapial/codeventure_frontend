# Skill: Create Next.js Page

## Project Architecture Overview

This frontend is a **Next.js 16 App Router + TypeScript** project using
**Tailwind CSS v4**, **TanStack Query** for server state, **React Hook Form**
for forms, and **Zod** (shared from `packages/contracts`) for validation.

```
codeventure_frontend/
├── src/
│   ├── app/                       ← App Router (Server Components by default)
│   │   ├── layout.tsx             ← Root layout, fonts, providers
│   │   ├── globals.css            ← Tailwind base + design tokens
│   │   └── <route>/
│   │       ├── page.tsx           ← Server Component shell (RSC)
│   │       ├── loading.tsx        ← Route-level loading UI
│   │       ├── error.tsx          ← Route-level error boundary
│   │       ├── not-found.tsx      ← Route-level 404
│   │       └── _components/       ← Client Components (colocated, private)
│   │           ├── <Feature>List.tsx
│   │           ├── <Feature>Card.tsx
│   │           └── <Feature>Form.tsx
│   ├── components/
│   │   ├── ui/                    ← shadcn/ui primitives (generated by CLI)
│   │   └── shared/                ← App-specific shared components
│   ├── lib/
│   │   ├── utils.ts               ← `cn()` helper (clsx + tailwind-merge)
│   │   ├── api/                   ← Typed API client, fetchers
│   │   └── queryKeys.ts           ← Centralized TanStack Query keys
│   ├── hooks/                     ← Reusable client hooks
│   ├── styles/                    ← Design tokens, Tailwind layer overrides
│   └── types/                     ← Shared TS types (re-export from contracts)
└── components.json                ← shadcn config (commit; never delete)
├── public/                        ← Static assets
└── next.config.ts                 ← reactCompiler: true
```

**Path alias:** `@/*` → `./src/*` (see `tsconfig.json`).  
**API base URL:** read from `NEXT_PUBLIC_API_BASE_URL`, must end without
trailing slash; routes are mounted under `/api/v1` on the backend.

## Non-Negotiable Frontend Rules (from the master skill)

- Prefer **Server Components** for shells and initial read-only data.
- **Client Components** only for browser interactivity (`"use client"`).
- Use a **typed API layer**; do not scatter raw `fetch` calls.
- List filter/sort/page state lives in **URL parameters**.
- Every page implements: **loading**, **empty**, **error**, **forbidden /
  not-found**, and **success** states.
- Forms use **React Hook Form** + shared **Zod** schemas from
  `packages/contracts`.
- Preserve **costly drafts** and **unsent messages**.
- Meet **WCAG 2.2 AA** (semantic landmarks, focus rings, keyboard, contrast).
- Use **CodeVenture design tokens**; no random feature colors.
- Animation must **never delay** content or primary actions.

## UI Components — shadcn/ui (REQUIRED)

CodeVenture uses **shadcn/ui** for every primitive (Button, Input, Dialog,
Select, Toast, etc.). Do **not** import arbitrary component libraries, do
**not** hand-roll buttons/inputs that duplicate shadcn primitives, and do
**not** introduce random feature colors. Shadcn copies the source into
`src/components/ui/` so we own the code and can theme it with CodeVenture
tokens.

> Status note: the repo does not yet contain `components.json` or
> `src/components/ui/`. Run §1.0 once per environment before writing any
> page that imports from `@/components/ui/...`.

### 1.0 Initialize shadcn/ui (one-time, per environment)

Run the CLI once per machine — it is interactive, so use the pre-seeded


`.dark` in `globals.css`. Map them to **CodeVenture semantic tokens**
before adding primitives — otherwise we leak shadcn defaults:

```css

    --background:        0 0% 100%;

    --destructive:       0 84% 60%;
    --destructive-foreground: 210 40% 98%;

    --border:            214 32% 91%;
    --input:             214 32% 91%;
    --ring:              221 83% 53%;

    --radius:            0.5rem;
  }

    --background:        222 47% 6%;
    --foreground:        210 40% 98%;
    --primary:           217 91% 60%;

```

After mapping, **the existing skill examples already work** — they import

### 1.2 Composing primitives (the only allowed pattern)

```tsx
import { Button } from "@/components/ui/button";
import { Input } from "@/components/ui/input";
import { Label } from "@/components/ui/label";
import { toast } from "sonner";

export function SaveFeatureForm() {
  return (
    <form className="space-y-4">
      <div className="space-y-2">
        <Label htmlFor="title">Title</Label>
        <Input id="title" name="title" placeholder="e.g. Quote request" />
      </div>
      <Button type="submit" onClick={() => toast.success("Saved")}>
        Save
      </Button>
    </form>
  );
}
```

Rules:

- Import from `@/components/ui/<name>` — the lowercase path the CLI
  generates. Never import directly from Radix or `radix-ui/react-*`.
- Use the `cn()` helper from `@/lib/utils` when composing class names.
- Toasts go through `sonner` (mounted once in the root layout — see §13).
- If a primitive is missing, **add it via the CLI** rather than copying
  snippets from the web:
  `npx shadcn@latest add <component>`.

### 1.3 Forbidden (will fail review)

- ❌ `import { Button } from "@mui/material"` or any other UI kit.
- ❌ Hand-rolled `<button className="bg-blue-500 …">` that duplicates
  shadcn `Button`.
- ❌ Editing a file inside `src/components/ui/` to add a one-off color
  variant — extend `globals.css` tokens instead, or add a `variants` entry
  via `cva` in the component file (preserve shadcn's structure).
- ❌ Re-running `init` after primitives exist (it will overwrite).

## Step-by-Step: Adding a New Page

### 1. Decide Server vs. Client

Ask: does the page need browser state, event handlers, refs, or lifecycle?

- **No** → Server Component in `page.tsx`. Fetch with the typed API layer on
  the server (e.g. inside an `async` component or a small data function).
- **Yes** → `page.tsx` stays a Server Component for shell + initial data;
  interactivity lives in a colocated `_components/<Name>.tsx` `"use client"`
  module.

Never mark `page.tsx` `"use client"` unless the whole page is interactive
(rare). Never put `fetch` inside a Client Component when the data is static
or initial.

### 2. Create the route folder

```
src/app/<route>/
├── page.tsx
├── loading.tsx
├── error.tsx
├── not-found.tsx            (only if the route has its own 404 semantics)
└── _components/
    └── <Feature>.tsx
```

Underscored folders (`_components`) are **private to the route** — they do
not become URL segments.

### 3. `loading.tsx` — Route loading skeleton

```tsx
// src/app/<route>/loading.tsx
import { Skeleton } from "@/components/ui/skeleton";

export default function Loading() {
  return (
    <main className="mx-auto max-w-5xl p-6" aria-busy="true" aria-live="polite">
      <Skeleton className="mb-4 h-8 w-1/3" />
      <Skeleton className="h-64 w-full" />
    </main>
  );
}
```

### 4. `error.tsx` — Route error boundary

```tsx
// src/app/<route>/error.tsx
"use client";

import { useEffect } from "react";
import { Button } from "@/components/ui/button";

export default function RouteError({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  useEffect(() => {
    console.error("Route error:", error);
  }, [error]);

  return (
    <main className="mx-auto max-w-2xl p-6 text-center">
      <h1 className="text-2xl font-semibold">Something went wrong</h1>
      <p className="mt-2 text-muted-foreground">
        We could not load this page. Please try again.
      </p>
      <Button className="mt-6" onClick={reset}>Retry</Button>
    </main>
  );
}
```

### 5. `page.tsx` — Server Component shell

```tsx
// src/app/<route>/page.tsx
import { notFound } from "next/navigation";
import { fetchFeature } from "@/lib/api/feature";
import { FeatureView } from "./_components/FeatureView";

interface PageProps {
  params: Promise<{ id: string }>;
  searchParams: Promise<Record<string, string | string[] | undefined>>;
}

export default async function FeaturePage({ params, searchParams }: PageProps) {
  const { id } = await params;
  const sp = await searchParams;

  const result = await fetchFeature(id);

  if (!result.ok) {
    if (result.status === 404) notFound();
    // For 403 the caller should render a forbidden state — see FeatureView.
    return <FeatureView data={null} error={result} />;
  }

  return <FeatureView data={result.data} />;
}
```

Notes:

- `searchParams` is always URL-as-state. Coerce and validate with Zod before
  passing to the fetcher.
- Return `notFound()` from `next/navigation` for true 404s; render a
  forbidden state for 403.

### 6. `_components/<Feature>.tsx` — Client Component

```tsx
// src/app/<route>/_components/FeatureView.tsx
"use client";

import { useQuery } from "@tanstack/react-query";
import { featureKeys } from "@/lib/queryKeys";
import { fetchFeature } from "@/lib/api/feature";
import { Button } from "@/components/ui/button";
import { Skeleton } from "@/components/ui/skeleton";
import { EmptyState } from "@/components/ui/empty-state";
import { ForbiddenState } from "@/components/ui/forbidden-state";
import type { ApiResult } from "@/lib/api/types";

type Props = {
  initialData?: FeatureDto | null;
};

export function FeatureView({ initialData }: Props) {
  const query = useQuery({
    queryKey: featureKeys.detail(initialData?.id ?? ""),
    queryFn: () => fetchFeature(initialData!.id),
    enabled: !!initialData?.id,
    initialData: initialData ? { ok: true, status: 200, data: initialData } : undefined,
  });

  // Loading (only meaningful on refetch)
  if (query.isPending) {
    return (
      <main className="mx-auto max-w-3xl p-6" aria-busy="true">
        <Skeleton className="h-8 w-1/2" />
        <Skeleton className="mt-4 h-48 w-full" />
      </main>
    );
  }

  // Error
  if (query.isError) {
    return (
      <main className="mx-auto max-w-2xl p-6 text-center">
        <h1 className="text-2xl font-semibold">Something went wrong</h1>
        <Button className="mt-4" onClick={() => query.refetch()}>Retry</Button>
      </main>
    );
  }

  const result = query.data as ApiResult<FeatureDto>;

  if (result.status === 403) return <ForbiddenState />;
  if (result.status === 404) return <EmptyState title="Not found" />;
  if (!result.ok) return <EmptyState title="Unable to load" />;

  // Empty
  if (!result.data) {
    return <EmptyState title="No data yet" description="Nothing to show here." />;
  }

  // Success
  return (
    <main className="mx-auto max-w-3xl p-6">
      <h1 className="text-3xl font-semibold">{result.data.title}</h1>
      <p className="mt-4 text-muted-foreground">{result.data.description}</p>
    </main>
  );
}
```

### 7. Typed API client

Never `fetch` directly inside a component. Centralize in `src/lib/api/`:

```ts
// src/lib/api/feature.ts
import { apiFetch, type ApiResult } from "./client";
import { featureSchema, type FeatureDto } from "@/types/feature";

export async function fetchFeature(id: string): Promise<ApiResult<FeatureDto>> {
  return apiFetch(`/features/${id}`, { schema: featureSchema });
}

export async function listFeatures(query: ListQuery): Promise<ApiResult<FeatureDto[]>> {
  const qs = new URLSearchParams(query as Record<string, string>).toString();
  return apiFetch(`/features?${qs}`, { schema: z.array(featureSchema) });
}
```

`apiFetch` is responsible for:

- Building the URL from `NEXT_PUBLIC_API_BASE_URL + "/api/v1"`.
- Forwarding cookies on the server (`cookies()` from `next/headers`).
- Parsing + Zod-validating the response.
- Mapping non-2xx to a typed `ApiResult` (NEVER throws to React tree for
  expected business states like 403/404).

### 8. Forms — React Hook Form + Zod

```tsx
"use client";

import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { featureCreateSchema, type FeatureCreateInput } from "@/types/feature";
import { Button } from "@/components/ui/button";

export function FeatureForm({ onSubmit }: { onSubmit: (v: FeatureCreateInput) => void }) {
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting, isDirty },
  } = useForm<FeatureCreateInput>({
    resolver: zodResolver(featureCreateSchema),
    defaultValues: { title: "", description: "" },
  });

  return (
    <form
      onSubmit={handleSubmit(onSubmit)}
      className="space-y-4"
      aria-describedby={errors.root ? "form-error" : undefined}
      noValidate
    >
      <div>
        <label htmlFor="title" className="block text-sm font-medium">
          Title
        </label>
        <input
          id="title"
          {...register("title")}
          className="mt-1 w-full rounded border bg-background p-2"
          aria-invalid={!!errors.title}
        />
        {errors.title && (
          <p role="alert" className="mt-1 text-sm text-destructive">
            {errors.title.message}
          </p>
        )}
      </div>

      <Button type="submit" disabled={isSubmitting || !isDirty}>
        {isSubmitting ? "Saving…" : "Save"}
      </Button>
    </form>
  );
}
```

Drafts: persist unsent input to `sessionStorage` (or a store) so the user
does not lose work on accidental navigation.

### 9. Required UI states — checklist

Every route MUST implement:

- [ ] **Loading** — `loading.tsx` for the route, plus inline skeletons for
       client refetches.
- [ ] **Empty** — explicit `EmptyState` when the data is `[]` / `null`.
- [ ] **Error** — `error.tsx` boundary + per-mutation retry.
- [ ] **Forbidden** — when API returns 403, render `<ForbiddenState />` (do
       NOT redirect to login if the user is authenticated but unauthorized).
- [ ] **Not found** — `notFound()` from server, or `<EmptyState title="Not
       found" />` on the client.
- [ ] **Success** — render the data with semantic landmarks and headings.

### 10. Accessibility (WCAG 2.2 AA)

- One `<h1>` per page.
- Every input has an associated `<label htmlFor>`.
- Errors use `role="alert"` or `aria-live="polite"`.
- Visible focus ring (do not remove `outline` without a replacement).
- Color is never the only signal (pair with text or icon).
- Keyboard: tab order is logical; modals trap focus; ESC closes.
- Respect `prefers-reduced-motion`.

### 11. Design tokens

Use semantic Tailwind tokens that map to CodeVenture design tokens. Do NOT
introduce one-off colors like `bg-pink-300` — extend the theme in
`globals.css` if a new semantic color is genuinely needed.

```tsx
<button className="bg-primary text-primary-foreground hover:bg-primary/90" />
<text className="text-muted-foreground" />
```

### 12. Cache invalidation (TanStack Query)

After every successful mutation, invalidate the relevant query keys:

```ts
queryClient.invalidateQueries({ queryKey: featureKeys.all });
```

Centralize query keys in `src/lib/queryKeys.ts`:

```ts
export const featureKeys = {
  all: ["features"] as const,
  list: (q: ListQuery) => ["features", "list", q] as const,
  detail: (id: string) => ["features", "detail", id] as const,
};
```

### 13. Providers & Toaster mount (root layout)

Once shadcn is initialized, the root `layout.tsx` MUST wrap the tree with
the TanStack Query provider and mount the Sonner toaster exactly once.
Create `src/app/providers.tsx`:

```tsx
"use client";

import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { ReactNode, useState } from "react";
import { Toaster } from "@/components/ui/sonner";

export function Providers({ children }: { children: ReactNode }) {
  const [client] = useState(() => new QueryClient({
    defaultOptions: {
      queries: { staleTime: 30_000, refetchOnWindowFocus: false, retry: 1 },
    },
  }));
  return (
    <QueryClientProvider client={client}>
      {children}
      <Toaster richColors closeButton position="top-right" />
    </QueryClientProvider>
  );
}
```

Then in `src/app/layout.tsx`:

```tsx
import { Providers } from "./providers";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" className="h-full antialiased">
      <body className="min-h-full flex flex-col bg-background text-foreground">
        <Providers>{children}</Providers>
      </body>
    </html>
  );
}
```

Call toasts from anywhere via `import { toast } from "sonner"`.

## URL-as-state for lists

Page, sort, filter, and search belong in the URL. Read with `searchParams`
on the server; update with `useRouter().replace(...)` (shallow, no scroll).

```ts
const sp = await searchParams;
const page = Number(sp.page ?? 1);
const sort = String(sp.sort ?? "createdAt:desc");
const search = String(sp.q ?? "");
```

Validate with Zod; fall back to safe defaults on parse failure.

## Forbidden Patterns

- ❌ Raw `fetch(...)` inside a Client Component.
- ❌ `"use client"` at the top of `page.tsx` (unless truly interactive).
- ❌ `localStorage` for sensitive session data.
- ❌ `any` to silence types — use `unknown` and narrow.
- ❌ Swallowing errors with `.catch(() => {})` — surface them.
- ❌ `bg-[#ff00aa]` / arbitrary feature colors.
- ❌ Hidden modals without focus trap or ESC handling.
- ❌ Loading the whole library client-side when a Server Component could
  have shipped the initial payload.

# Testing with Vitest

This section is the canonical reference for writing and running unit / integration
tests across **both** the backend (`codeventure_backend`) and frontend
(`codeventure_frontend`). Vitest is the single runner; each project wires it up
independently with the same mental model.

> **Rule of thumb:** every new module ships with a test file. If a change adds
> any non-trivial logic — Zod schema, API fetcher, controller, hook, form
> validation — add or update the matching spec before merging.

### 1.4 Patterns

```ts
// src/modules/auth/auth.validation.test.ts
import { describe, expect, it } from "vitest";
import { signInSchema } from "./auth.validation";
```

### 2.6 Auth & Public Page Patterns

P16-P21 added the post-sign-in surfaces (2FA verify, register, verify-email) and
public legal pages. They share a small set of conventions worth capturing here
so future agents don't have to rediscover them.

#### Page route layout

```
src/app/
├── (auth)/
│   ├── 2fa/page.tsx              ← Server Component: session check + render <Verify2FAForm/>
│   ├── 2fa/_components/verify-2fa-form.tsx
│   ├── register/page.tsx
│   ├── register/_components/register-form.tsx
│   └── verify-email/page.tsx
└── legal/[slug]/
    ├── page.tsx                  ← Server Component: apiFetch with ISR tag
    └── not-found.tsx
```

Conventions:
- The `page.tsx` is a **Server Component**. It calls `getSession()` from
  `src/lib/auth/session` (which imports `server-only`) and `redirect()`s to the
  appropriate route when the user is in the wrong auth state (already signed
  in, missing challenge cookie, etc.).
- The interactive form lives at `<route>/_components/<feature>-form.tsx` and is
  marked `"use client"`. The underscore prefix keeps it out of the routing tree.
- The page passes nothing to the form unless it's derived server-side (e.g. a
  `challengeToken` read from cookies). Static copy stays in the form.

#### Server Component session check

```tsx
// src/app/(auth)/2fa/page.tsx
import { redirect } from "next/navigation";
import { getSession } from "@/lib/auth/session";
import { Verify2FAForm } from "./_components/verify-2fa-form";

export default async function Verify2FAPage() {
  const session = await getSession();
  if (!session) redirect("/sign-in");
  if (!session.requires2FA) redirect("/");

  return (
    <main>
      <Verify2FAForm />
    </main>
  );
}
```

`getSession()` is itself a Server-Component-only helper (`import "server-only"`
at the top of `src/lib/auth/session.ts`). Tests stub it via
`vi.mock("@/lib/api/auth", () => ({ fetchSession: vi.fn(...) }))` and the
`cookies()` call via `vi.mock("next/headers", ...)`.

#### Client form with `zodResolver`

```tsx
// src/app/(auth)/2fa/_components/verify-2fa-form.tsx
"use client";

import { useRouter } from "next/navigation";
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { twoFactorVerifySchema, type TwoFactorVerifyInput } from "@/types/auth";
import { verifyTwoFactor, ApiError } from "@/lib/api/auth-2fa";

export function Verify2FAForm() {
  const router = useRouter();
  const { register, handleSubmit, formState, setError } =
    useForm<TwoFactorVerifyInput>({ resolver: zodResolver(twoFactorVerifySchema) });

  async function onSubmit(values: TwoFactorVerifyInput) {
    try {
      await verifyTwoFactor(values);
      router.replace("/");
      router.refresh();
    } catch (err) {
      if (err instanceof ApiError && err.body.code === "INVALID_2FA_CODE") {
        setError("code", { message: "That code didn't work. Try again." });
      } else {
        setError("root", { message: "Something went wrong. Please retry." });
      }
    }
  }

  return ( /* … */ );
}
```

Notes:
- The schema is the **single source of truth** — type the form off
  `z.infer<typeof …>` rather than redefining a `FormValues` type.
- `setError("code", …)` writes to a specific field. `setError("root", …)`
  surfaces a form-wide banner.
- Always `router.refresh()` after a successful auth mutation so Server
  Components re-read the session cookie.

#### `apiFetch` + `ApiError` helper convention

Every API helper module under `src/lib/api/` follows the same shape:

```ts
// src/lib/api/auth-2fa.ts
import { apiFetch, type ApiResult } from "./client";
import { ApiError } from "./auth";                  // ← ApiError lives here
import { type TwoFactorVerifyInput } from "@/types/auth";

export async function verifyTwoFactor(payload: TwoFactorVerifyInput) {
  const result: ApiResult<{ ok: true }> = await apiFetch("/auth/2fa/verify", {
    method: "POST",
    body: payload,
    forwardCookies: true,                          // sets cv_session cookie
  });

  if (!result.ok) throw new ApiError(result.status, result.error.error);
  return result.data;
}
```

Rules:
- **`apiFetch` does not throw.** It returns
  `ApiResult<T> = { ok: true; status; data: T } | { ok: false; status; error: { error: EnvelopeError } }`.
- The helper, not the form, translates `!result.ok` into `new ApiError(status, envelopeError)`.
  `ApiError` is exported from `./auth` (not `./client`).
- `forwardCookies: true` is required for any endpoint that sets `cv_session`
  (`/auth/2fa/verify`, `/auth/register`, `/auth/verify-email/confirm`).
  Leave it off for `/auth/2fa/resend` etc.

#### Testing API helpers

Mock the transport, drive the helper, assert on the call shape and the thrown
`ApiError`. **Do not** chain two `.rejects` assertions on the same promise — the
second `await` re-invokes the helper with no fresh mock and throws a TypeError.
Use one explicit try/catch:

```ts
// src/lib/api/auth-2fa.test.ts
import { describe, expect, it, vi } from "vitest";

vi.mock("./client", () => ({
  apiFetch: vi.fn(),
  ApiTransportError: class extends Error {},         // shape only
}));
vi.mock("./auth", () => ({
  ApiError: class ApiError extends Error {
    constructor(public status: number, public body: { code: string; message: string }) {
      super(body.message);
    }
  },
}));

import { apiFetch } from "./client";
import { ApiError } from "./auth";
import { verifyTwoFactor, resendTwoFactor } from "./auth-2fa";

describe("verifyTwoFactor", () => {
  it("posts the parsed body and forwards cookies on success", async () => {
    vi.mocked(apiFetch).mockResolvedValue({
      ok: true, status: 200, data: { ok: true } as never,
    });

    await expect(verifyTwoFactor({ code: "123456", challengeToken: "ct" }))
      .resolves.toEqual({ ok: true });

    expect(apiFetch).toHaveBeenCalledWith("/auth/2fa/verify", {
      method: "POST",
      body: { code: "123456", challengeToken: "ct" },
      forwardCookies: true,
    });
  });

  it("throws ApiError with the envelope on a 400", async () => {
    vi.mocked(apiFetch).mockResolvedValue({
      ok: false,
      status: 400,
      error: { error: { code: "INVALID_2FA_CODE", message: "Bad code" } },
    } as never);

    try {
      await verifyTwoFactor({ code: "000000", challengeToken: "ct" });
      throw new Error("expected ApiError");
    } catch (err) {
      expect(err).toBeInstanceOf(ApiError);
      expect(err).toMatchObject({
        status: 400,
        body: { code: "INVALID_2FA_CODE", message: "Bad code" },
      });
    }
  });
});
```

#### Honeypot field (register form)

`registerSchema` rejects any non-empty `website` field as a bot signal. Render
it offscreen so humans never fill it:

```tsx
<input
  type="text"
  tabIndex={-1}
  autoComplete="off"
  aria-hidden="true"
  className="absolute -left-[9999px] h-0 w-0 opacity-0"
  {...register("website")}
/>
```

If the bot fills it, `zodResolver` will short-circuit the submit with a
validation error and you never call `register()`.

#### ISR for public legal pages

`/legal/[slug]` is publicly cacheable. Use `apiFetch`'s `next` option to get
per-slug tag invalidation:

```tsx
// src/app/legal/[slug]/page.tsx
import { apiFetch } from "@/lib/api/client";
import { notFound } from "next/navigation";

export default async function LegalPage(
  { params }: { params: Promise<{ slug: string }> },
) {
  const { slug } = await params;
  const result = await apiFetch(`/public/legal/${slug}`, {
    next: { revalidate: 3600, tags: [`legal:${slug}`] },
  });
  if (!result.ok) notFound();

  return <article dangerouslySetInnerHTML={{ __html: result.data.bodyHtml }} />;
}
```

When a new legal version is published, hit
`revalidateTag(\`legal:${slug}\`)` (typically from a CMS webhook) to bust just
that document.

## 3. Shared rules

- **Co-locate** specs next to the file they cover. Mirror the file name and
  add `.test.ts` / `.test.tsx`.
- **No live network.** Mock `fetch`, `apiFetch`, `cookies()`, or `next/router`
  in unit tests. Reserve integration tests for a separate `tests/e2e/` folder
  using Playwright (out of scope for Vitest).
- **Reset between tests.** Use `beforeEach(() => vi.clearAllMocks())` and the
  setup-file `cleanup()` so state never leaks.
- **Type the mock.** Prefer `vi.mocked(apiFetch)` over `apiFetch as any` so
  autocomplete still works.
- **Don't test the framework.** If a spec is exercising how `useState` works,
  delete it. Test what your code does, not what React does.
- **One assertion per concept.** Group related expectations in a single `it`
  when they describe one behaviour; split them when they describe two.
- **Naming.** Spec titles read like sentences: `it("redirects to sign-in when
  the session is missing", ...)`.
